# 模拟面试评分标准与解析

先做完 [模拟面试题](mock.md)。每小题按下面的可观察要点给分，表述不同但机制等价时可以得分。出现矛盾时，用题设的时序或上下游边界重新解释。

## Java 后端 · 50 分

**M01 · 12 分**

- **4 分** 写入按旧哈希存储，改名后再查用新哈希，可能走到不同查找路径。相同对象引用无法保证命中旧条目。
- **4 分** 用不可变 `record StationKey(String mapId, String id) {}` 作为键，名称放到值里。编辑名称时更新值，键保持稳定。
- **4 分** 设计旧键改名前后的哈希不同，插入后改名再读取，观测取不到旧条目。再验证稳定键下同一编辑仍能查到，并且不同地图的同名 ID 能隔离。测试应控制输入，避免偶然哈希行为掩盖问题。

**M02 · 12 分**

- **4 分** v2 线程读到 v1、比较通过后暂停。v3 也读到 v1 并写入。v2 随后赋值，表回到 v2。
- **4 分** 将比较和赋值放入同一个同步块或使用正确的 CAS 循环。读者每个请求开始只读一次不可变引用，之后复用。
- **4 分** 两个闩锁强制失败实现交错，断言修复后最终版本为 3，并分别断言旧请求仍看到旧表、新请求看到新表。理解为什么 `volatile` 的可见性不足以覆盖两个动作。

**M03 · 13 分**

- **4 分** 同类调用绕过默认事务代理，`save` 的注解可能没有应用。把事务方法拆到另一个 Bean 或使用显式事务边界。
- **5 分** 采用来源加事件 ID 的稳定键，给组合键建唯一约束。去重记录、核对内容与业务更新在一个本地事务内，明确重复内容和同键冲突的处理。
- **4 分** 业务事务提交后推进消费进度。重投查到已提交的同一事件，只返回已处理结果。答案要能解释「提交成功但确认丢失」窗口。

**M04 · 13 分**

- **4 分** 提出 `(tenant_id, status, created_at)` 等适合等值前缀与时间范围的索引，用 `EXPLAIN` 和数据分布判断只按状态的查询。决策需考虑扫描成本和索引写开销。
- **4 分** 读者缓存未命中、查到旧值后被暂停。写者提交新值并删缓存。读者恢复，把旧值写回。
- **5 分** 给出与竞态相符的办法，例如配套维护版本标识的条件回填，或接受短 TTL 的陈旧窗口并明确时限。用可控时序复现，检查读者回填被拒绝或旧值按预期失效。

## AI Agent · 50 分

**M05 · 12 分**

- **4 分** 模型提出工具调用，应用累积参数、校验后执行，按调用标识把结果交回模型生成有依据的答案。
- **4 分** 等工具参数完成信号后解析与执行。订单号从参数取得，身份从可信登录上下文取得，服务端检查订单归属。
- **4 分** 应用可保存运行 ID、工具调用状态与结果或幂等键。重连按运行 ID 查询并尽量恢复展示，已执行步骤避免重复。区分 UI 断线和下游执行失败。

**M06 · 12 分**

- **4 分** 错误码精确搜索和语义召回结合，按车型、权限、生效版本约束候选。重排时保留必要的精确命中。
- **4 分** 引用明确文档、版本和段落或页码。证据缺失则说明未找到适用资料，并提示需要的版本信息。
- **4 分** 分别给出检索前 K 命中率一类指标和回答是否受到引用证据支持的指标。举例解释「正确段落进候选，最终仍写错」能分别如何得分。

**M07 · 13 分**

- **4 分** 先 initialize 协商版本和能力，再发 initialized 通知。就绪后发现及调用支持的工具。
- **5 分** 用稳定服务 ID 与工具名标识内部目标，将公开名称映射到该目标。列表按租户展示，执行时按当前授权重新检查调用者和资源。
- **4 分** 失效或刷新发现缓存，明确已有请求与新调用如何处理。日志记录请求标识、租户或其脱敏标识、配置版本、工具目标和结果。题目用固定 MCP 版本，实际版本要从部署确认。 [MCP 生命周期](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)

**M08 · 13 分**

- **5 分** 超时让最终结果未知。用由应用生成并跨重试复用的工单请求 ID 作为业务幂等键，在执行端按租户与键约束单次生效。明确拒绝可根据原因修正或结束。
- **4 分** 设步骤、总耗时和重复调用上限。未知结果时先查状态。还无法确认可答「请求已发出，工单是否创建仍待确认」，并提供能核查的请求标识。
- **4 分** 可用成功一次、超时但实际成功后重投、明确失败三例。检查最终业务状态和轨迹中的实际调用及判定。答复好听但生成两张工单应判失败。

## 怎么复习失分题

- 机制答对但没有时间线，回去补一张只包含关键读写的时序图。
- 方案答对但没有边界，补充失败、重试、超时或并发中的一个反例。
- 说了「加锁」「做鉴权」「上 RAG」但无法指认执行位置，回到对应题库，把它落到具体方法或数据流节点。
