# Java + Agent 模拟面试 · 45 分钟

满分 100 分，前四题考 Java 后端，后四题考 Agent。先闭卷，允许在纸上画图或写伪代码。每题先给结论，再指出你从题目哪条信息推断出来，最后说如何验证。共 40 分钟答题，留 5 分钟检查。

## Java 后端 · 50 分

### M01 · 站点索引突然查不到（12 分，4 分钟）

地图页面把一个可变 `Station` 作为 HashMap 键。它的 `equals` 和 `hashCode` 同时使用 `id` 与 `name`。插入后用户改了名称。随后按原对象查找，偶尔返回空。

1. 用桶和相等性解释这个结果。
2. 写一个适合作为键的 Java 定义，说明如何编辑名称。
3. 给出一个能测出旧实现问题的测试思路。

### M02 · 旧快照覆盖了新配置（12 分，5 分钟）

```java
private volatile Snapshot current;

void update(Snapshot next) {
    if (next.version() > current.version()) {
        current = next;
    }
}
```

1. 写出 v1 当前、v2 与 v3 并发更新时，最终可能停在 v2 的时序。
2. 给出最小改法，说明读者如何让同一次请求中的路由查询使用一致的版本。
3. 写出测试断言，并说明怎样让竞争可重现。

### M03 · 事务提交了，消费确认丢了（13 分，6 分钟）

订单积分消费者将余额写入 MySQL 后，提交 offset 失败。随后同一个事件重投。在当前代码中，`consume` 通过 `this.save()` 调用本类中带 `@Transactional` 的 `save`。

1. 解释默认代理模式下的事务边界风险。
2. 设计事件键、唯一约束和消费事务。
3. 补充 offset 何时推进，以及第一次已提交、第二次来时应该怎样处理。

### M04 · 慢 SQL 与旧缓存（13 分，5 分钟）

订单查询使用 `WHERE tenant_id=? AND status=? AND created_at>=?`。后台另有不带租户条件的状态统计。订单状态写入后，缓存偶尔显示旧值。

1. 给查询一个联合索引，并说明状态统计为什么要单独看执行计划。
2. 画出一种「提交数据库、删缓存后，旧值仍被回填」的时序。
3. 说出一个针对这个竞态的方案和它的代价，再给一个能稳定复现的测试办法。

## AI Agent · 50 分

### M05 · 流还没结束，工具参数只收到一半（12 分，4 分钟）

用户问「帮我查订单 O123」。模型先流出部分助手文本，再分片输出工具参数。两次片段分别是 `{"orderId":"O` 和 `123"}`。前端在工具执行后断线。

1. 画出从模型提出调用到最终回答的流程，注明每个步骤由谁负责。
2. 何时执行工具？用户和租户身份从哪里来？
3. 断线重连时如何得知工具到底执行没执行？

### M06 · RAG 引用了另一版本的手册（12 分，5 分钟）

问题包含型号 M02 与错误码 `E4027`。向量检索只找到了旧版手册，模型给出了很确定的答案。

1. 改进召回和过滤，并解释为什么。
2. 设计引用字段和证据缺失时的表现。
3. 给出一条检索指标和一条回答指标，各用一个示例解释。

### M07 · 两个 MCP 服务都有 query（13 分，5 分钟）

两个工具服务都暴露 `query`，各自服务不同租户。客户端之前缓存过工具列表，管理员刚修改了某租户的权限。

1. 以 2025-11-25 MCP 规范为例，说出准备好调用前的初始化过程。
2. 设计同名工具的映射和两次权限检查的位置。
3. 工具列表与权限变动可能怎样影响已有客户端？怎样记录足够的故障证据？

### M08 · 模型看起来成功，工具其实重复执行（13 分，6 分钟）

一个已配置的工单助手创建工单时遇到超时。模型下一轮又发一次同样的创建请求，最终用户收到了两张工单。

1. 区分超时和明确失败，设计一个可复用的业务幂等键。
2. 给出循环退出条件和一次无法确认执行结果时的用户答复。
3. 设计三条回归用例，以及判断通过需要查看的两类证据。
