# 13 · 机器人回断点后，从哪里继续扫？

设计题来自 AMR 的断点续扫场景。课堂用自造路线和到站消息，只练**续扫交接和进度保存**。看过 [10 异步发送和任务恢复](../10-route-recovery-lab/README.md) 会更容易理解发出去的进度和实际到站进度。

## 先看一个具体问题

机器人要沿 A → B → C → B → D 清扫。它在第二个 B 停下，回起点处理后，再空驶回 B。控制器这时发来一条“B 已到站”的反馈。要继续清扫，程序得回答两个问题。

1. 原任务里的 B 是第一次经过的 B，还是第二次经过的 B？
2. 这条反馈是不是本次回站的消息？车真的到断点附近了吗？

### 通俗解释

把路线当成排队打卡的站点清单。两行可以写同一个站名，打卡位置靠第几行来确定。再把回站看成一张单独的派工单。只有派工单编号、完成状态、到站名称和距离都对得上，才把原来的清扫清单交回去。

### 正式概念

- **路线版本**标识当时保存的是哪份站序。路线插站、删站或重排后，下标的含义可能变化。
- **完成站下标**从 0 开始。它表示最后一个完成的站。由它和下一站组成第一条未完成路段。
- **尝试编号**关联一次回站和它的反馈。本例假定每次回站由上游给出不同编号。
- **状态机**给每个阶段规定允许发生的事。课堂实现为单任务、顺序处理事件。
- **容差**是允许的到站距离上限。本例用 0.30 米，含等号。现场阈值和定位误差要结合控制器、地图和实际调试结论确定。

```text
原站序： A → B → C → B → D
下标：   0   1   2   3   4
                     ↑   │
                已完成下标  下一站
续扫站序：          [ B → D ]

WAITING ──开始回站──> RETURNING ──有效到站反馈──> READY
                           ↺ 旧反馈或条件未满足
```

## 完整示范

先按 [macOS 运行指南](../docs/macos.md) 运行本目录的 `RunLab.command`。基础输出为 `续扫站序 [B, D]`。使用 `--goal` 会继续验证迟到反馈、距离边界、重复反馈和旧地图版本。

| 时点 | 输入 | 预期 |
| --- | --- | --- |
| 1 | 快照 `v1, 3, B`，路线版本也是 `v1` | 可以建立交接状态 |
| 2 | 开始尝试 `return-2` | 状态变为 `RETURNING` |
| 3 | `return-2, B, 0.80 米, 已完成` | 超出容差，继续等待 |
| 4 | `return-2, B, 0.18 米, 已完成` | 确认到站，进入 `READY` |
| 5 | 取剩余站序 | `[B, D]` |

从 [CheckpointHandoffLab.java](src/cn/shiinapple/amr/handoff/CheckpointHandoffLab.java) 的 `main` 顺着读。到 [CheckpointHandoff.java](src/cn/shiinapple/amr/handoff/CheckpointHandoff.java) 时，依次看构造器怎样核对快照，`acceptArrival` 怎样筛掉无效反馈，最后看 `remainingStations` 如何保留断点站。这里留着 B，后续代码才能得到完整的 B → D 起终点。

## 独立练习

1. **换一条路线。** 把站序改为 S → X → Y → X → Z → T，断点为下标 3。先在纸上写出剩余两段，再增加断言核对。完成标准是站序为 `[X, Z, T]`。
2. **取消回站。** 增加取消操作，仅在 `RETURNING` 可用。取消后清除旧尝试，回到 `WAITING`。重新用不同编号启动，旧反馈要被拒绝，新反馈通过后才能继续。为四次变化分别写断言。

## 自测题

1. 有人用 `stations.indexOf("B")` 恢复原例，程序会返回哪一段？为什么这个实现容易在简单路线里通过测试？
2. 如果反馈站名正确、距离 0.10 米，但尝试编号是上一轮的，它能进入 `READY` 吗？
3. 设备说“请求已接收”时，能把 `completedStationIndex` 推到目标站吗？

## 答案与解析

1. `indexOf` 找第一次出现的位置，下标为 1，会从 B → C 重新扫。判断线索是重复站名。在每站只出现一次的路线中，名称碰巧能唯一定位。
2. 不能。判断线索是反馈的归属。旧反馈可能晚到，距离正确也无法证明本轮回站已经完成。
3. 不能。接收表示控制器收到了命令，完成进度要以对应反馈为据。复习 [10 异步发送和任务恢复](../10-route-recovery-lab/README.md) 中的 `sent` 和 `done`。

## 面试怎么讲

先画重复站名的路线解释数据建模，再讲空驶回站、到站核对、清扫接续三个动作各依赖什么证据。被问“跑过吗”，可以指出本题覆盖的模拟事件。要确认工业现场行为，还得结合控制器应答、到站反馈、位姿和清扫开关记录。
